# Auto routing в Polza Cowork

## Что работает сейчас

Новый чат в сборке Polza открывается в режиме **Auto**. Перед отправкой первого
сообщения роутер определяет тип задачи и язык результата, проверяет доступные
CLI и выбирает провайдера, модель и допустимый уровень усилия. Выбор модели
вручную отключает Auto для этого запуска. Существующий чат остаётся у своего
провайдера: смена CLI в середине истории пока создаёт отдельный чат.

Первичные правила — **не бенчмарки**. Для цепочек они выбирают Claude Sonnet,
для кода и анализа Codex Sol, для небольших задач Codex Luna. Если модель
недоступна, берётся доступная альтернатива. Русские и английские цепочки
разделяются по языку требуемых писем, а не языку команды пользователя.
Явное указание языка имеет приоритет; «цепочка для США/UK» тоже считается
английской. Если рынок и язык расходятся или не названы, пользователь должен
уточнить язык перед отправкой готовой цепочки.

Gemini не участвует в Auto до подтверждения платного режима и условий обработки
клиентских данных. Бесплатный API Google нельзя использовать для приватных
брифов и переписок. Ручной выбор Gemini остаётся виден пользователю.

## Как заполнять бенчмарки

1. Составьте реестр доступных маршрутов: провайдер, точный ID модели, effort,
   доступные инструменты, условия обработки данных, лимит и дата проверки цены
   входных и выходных токенов. Меняйте запись при смене тарифа или модели.
2. Для каждой категории (`chain`, `code`, `analysis`, `general`) и языка (`ru`,
   `en`) соберите минимум 12 **обезличенных** задач. Каждую модель-кандидата
   запускайте на одних и тех же задачах с одним брифом, материалами, правами и
   форматом ответа. RU/EN цепочки — отдельные наборы; язык задания не подменяет
   язык адресата. Не сравнивайте ответы по разным клиентам как парные прогоны.
3. Сохраняйте версию модели, effort, версию промпта, входные/выходные токены,
   фактическую цену вызова и время до результата. Слепой редактор отмечает
   принятие результата и минуты правок. Для цепочек проверяйте ICP, оффер,
   факты, естественность **именно нужного языка**, персонализацию, CTA,
   ограничения доставляемости и пригодность к отправке. Самооценка модели не
   считается результатом.
4. Для задач с инструментами считайте подтверждённое завершение задачи, а не
   красивый текст. Для запуска кампании отдельный обязательный gate: адресаты,
   лимиты, расписание и права в Portal; тест черновика не разрешает отправку.

Порог для маршрутизации по бенчмарку: минимум 12 оценок и не менее 80%
принятых результатов. Среди прошедших вариантов выбирается минимальная
`(цена токенов + стоимость правок) / доля принятых`. Вес минуты правок в коде
пока равен $0.50 как настройка алгоритма; это не оценка зарплаты. После
измерения реальных затрат его надо откалибровать. API-прайс не равен
предельной цене запроса по подписке Claude или Codex: подписки и лимиты вести
отдельным бюджетом.

Оценки добавляются в `POLZA_ROUTER_BENCHMARKS` в
`packages/client/src/lib/polzaAutoRouter.ts` только из проверенного и
версионированного набора. Переснимать выбор после смены модели, промпта,
инструментов или цены. Отложенные задачи не использовать для настройки
правил. Фактические qualified replies и встречи оценивать отдельно от
качества черновика; на них влияет кампания, база и клиент.

## Следующий слой

Реальный запуск цепочки должен оставаться действием Portal с проверкой
адресатов, лимитов, расписания и прав пользователя. Модель готовит и проверяет
данные, но не отправляет письма сама. Для перехода между разными CLI в одной
задаче нужен объект задачи поверх нескольких чатов и аудит каждого этапа.
