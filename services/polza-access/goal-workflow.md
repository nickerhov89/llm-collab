# Goal и Google Docs: рабочий порядок

Обновлено 19.11.2026. Goal проверяет результат, но не заменяет план работ.
Если владелец просит все подходящие материалы, отбор подходящих входит в задачу.
Не требуй повторно выбрать уже порученный объём; зафиксируй конкретный список
и причины исключений. После feedback «не выполнено» следующим действием должен
быть конкретный шаг через инструмент, а не очередное повторение статуса.
Реальный блокер (доступ, разрешение на внешнюю публикацию, обязательное решение)
покажи один раз с доказательством. Не объявляй цель выполненной без артефактов.
Не придумывай необходимость подтверждать подготовку уже заказанных черновиков.

Docs: `docs.update` теперь возвращает replies. Для addDocumentTab получи
replies[0].addDocumentTab.tabProperties.tabId и используй ID для следующих
insertText.location.tabId. Ответ хранится со стабильным idempotency_key.
Повторный тот же ключ не создаёт вторую вкладку. needs_review — не повторять
операцию с новым ключом, сначала проверить исход предыдущей.

Для картинок НЕ требуется публичное хранилище: собери DOCX с локальными
встроенными изображениями (python-docx), затем вызови:
`polza-docx /absolute/path/article.docx "Заголовок" stable-operation-key`
Команда создаёт новый нативный Google Doc через корпоративный OAuth, возвращает
URL; до 8 MiB. Никаких public/anyone permissions и публичных URL изображений.
Изображения вставляются в DOCX через add_picture, не только как подписи/ссылки.
Старые Google Doc не удалять и не заменять без отдельного поручения.

В Google сохраняются рабочие черновики с источниками. Внешние сайты, СМИ,
редакторы, почта, публикации — только по существующим правилам согласования;
данная инструкция не разрешает отправку или публикацию. Не выдумывай правовой
проверки: спорное утверждение пометь для проверки, не останавливая остальной
разрешённый пакет из-за него. Секреты и содержимое vault не копировать.

Готовый Python с python-docx и Pillow: `/home/manager/.local/share/polza/venvs/rich-docs/bin/python`.
